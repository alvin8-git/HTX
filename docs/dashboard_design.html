Design notes

Why the console is shaped this way, and what it still needs from upstream.

NOT TESTED is never a status colour It gets the neutral hatch instead. The four status hues mean good / warning / serious / critical; an unexamined agent is none of those. This is the single rule that stops the dashboard from turning a coverage gap into a clean bill of health.
Two ladders, never merged A swab gets NO ACTION → MONITOR → INVESTIGATE → ESCALATE. A taxon row gets NO_ACTION → MONITOR → CONFIRM → ESCALATE. They share colours because they share severity, but the legends name which ladder is in play.
"Number of swabs" is a stat tile, not a pie A single total has nothing to divide, so a pie of it would be one full circle. The two pies that survive are the ones with real parts: sample verdicts (4 classes) and species tiers (5 classes, with the 0.2% CONFIRM pulled out and labelled so it cannot vanish).
Site location is not yet captured Site names here come from the run notes, keyed by hand. To make the grid real, the sample sheet needs a stable site_id plus collected_at, carried through the PFI report filename — that filename is already the engine's only provenance key.
Every chart has a table twin Nothing is reachable by hover alone. Tooltips add convenience; the table carries the values, so the page holds up under a screen reader, in print, and in a PDF pasted into a report.
Explainability is the reason string, not a score The queue shows what the engine wrote, unedited, including its own hedges — "CO-LOCATION, NOT CO-ATTRIBUTION". A confidence percentage would be easier to render and much harder to defend.
